1. INTRODUCTION                                               *diffmerge-intro*

DiffMerge shows git comparisons in Vim's own diff mode (|diff|): filler lines,
scroll binding, folding of unchanged text and |]c| / |[c| work as usual.
Changes are moved by pointing at them: staging, unstaging and discarding a
line or hunk, picking a side of a conflict. Every view states the git command it is equivalent to, so there are no
surprises from git's point of view.

- Working tree files are the real buffers: edit and |:w| them.
- The index is an editable buffer: |:w| writes it to the index.
- Merges start from git's merge result: its conflict blocks show the BASE text
  (no conflict markers) until you resolve them.

Requires Neovim 0.12+ and git 2.23+. Mini.icons (files and folders) or 
nvim-web-devicons (files) are used for icons when available.

2. SETUP                                                      *diffmerge-setup*

With lazy.nvim: >lua
    {
      "XobSod/nvim-diffmerge",
      cmd = "DiffMerge",
      opts = {},
      keys = {
        { "<leader>do", "<CMD>DiffMerge<CR>", desc = "Status" },
        { "<leader>dl", "<CMD>DiffMerge log<CR>", desc = "Log (show / hide)" },
        { "<leader>df", "<CMD>DiffMerge files<CR>", desc = "Files (show / hide)" },
        { "<leader>dh", "<CMD>DiffMerge history<CR>", desc = "History (file)" },
        { "<leader>dh", ":DiffMerge history<CR>", mode = "x", desc = "History (lines)" },
        { "<leader>dc", "<CMD>DiffMerge conflicts<CR>", desc = "Conflicts" },
        { "<leader>dq", "<CMD>DiffMerge close<CR>", desc = "Close" },
      },
    }
<
`require("diffmerge").setup(opts)` is optional; defaults are used otherwise.

3. COMMANDS                                                *diffmerge-commands*

                                                                  *:DiffMerge*
:DiffMerge [status]     Status view: Conflicts / Staged / Unstaged / Untracked
                        (what `git status` shows), with the log of the
                        repository below it (`gL` shows / hides it,
                        |diffmerge-log|). One per repository: re-used, back on
                        the working tree. Opened from a file with changes it
                        shows that file, with the cursor on the same line.

:DiffMerge conflicts    Status view with the cursor on the first conflict (or
                        on the current file, if it is in conflict).

:DiffMerge diff [args] [-- paths]
                        Any `git diff` comparison, e.g. >vim
                          :DiffMerge diff HEAD~3
                          :DiffMerge diff --staged
                          :DiffMerge diff main...HEAD -- lua/
                          :DiffMerge diff v1.0 v2.0
                          :DiffMerge diff abc123^!
<
:DiffMerge log [git log args] [-- paths]
                        The status view with its log shown: the commit graph,
                        all branches by default (like `git log --graph
                        --branches --remotes`). In a status view (no
                        arguments; also one of a history): shows / hides its
                        log, like `gL`. With arguments, a view of its own:
                        that log, and the status of those paths only.

:DiffMerge history [path]
                        A view of the history of a file or directory (default:
                        current file) and its status. Single files follow
                        renames.
:'<,'>DiffMerge history History of the selected lines (`git log -L`).

:DiffMerge compare [left right]
                        Two files, or two directories (with a file panel),
                        side by side; both sides are editable (binary files
                        and a missing side show a placeholder). Symbolic links
                        show the file they point to. Directory compares leave
                        out `.git`, follow links to directories only inside
                        the compared directories, and drop a file from the
                        list once saved the same as its other side (`R`
                        compares everything again). A file open in another
                        Neovim is shown read-only. `%` / `#` at the start of
                        an argument are the current / alternate file (`%.orig`,
                        `%:h/b.txt`); nothing else is expanded. Started
                        without arguments, they are taken from the argument
                        list, e.g. a shell alias: >sh
                          alias dmdiff='nvim -c "DiffMerge compare" --'
                          dmdiff old.txt new.txt
<
:DiffMerge switch [args]
                        `git switch [args]`; without args a picker of the
                        branches (|diffmerge-branches|).

:DiffMerge fetch [args]
:DiffMerge pull [args]
:DiffMerge push [args]  git fetch / pull / push in the background
                        (|diffmerge-remote|).

:DiffMerge commit [args]
                        `git commit [args]`, the message edited in a window
                        below (|diffmerge-commit|).

:DiffMerge continue
:DiffMerge skip
:DiffMerge abort        The merge, rebase, cherry-pick, revert or `git am`
                        going on: continued, the commit being applied left
                        out, or aborted (|diffmerge-operation|).

:DiffMerge difftool [left right [name]]
:DiffMerge mergetool [local base remote merged]
                        Entry points for |diffmerge-git|. Started without
                        arguments, the files are taken from the argument
                        list.

:DiffMerge close        Close the view of the current tab.
:DiffMerge close_all    Close every view (e.g. before saving a session:
                        auto-session `pre_save_cmds = { "DiffMerge close_all" }`).
:DiffMerge refresh      Refresh the view.
:DiffMerge layout [name]
                        Cycle or set the layout (|diffmerge-layouts|).
:DiffMerge files        Show / hide the file panel, like `gF`.
:DiffMerge focus_files  Focus the file panel.
:DiffMerge abort        (git mergetool) Quit reporting failure to git; elsewhere
                        it aborts the operation going on (see above).

==============================================================================
4. VIEWS                                                      *diffmerge-views*

Every view is a tabpage: file panel on the left, log panel at the bottom
(status views, `gL`), diff windows in the rest. Closing the tab closes the
view.

Every side is labelled in its window bar. Breadcrumb plugins that write the
winbar of LSP buffers (e.g. lspsaga's symbol_in_winbar) should skip diff
windows; see the Compatibility section of the README for lspsaga.

                                                            *diffmerge-layouts*
Layouts describe how the windows are arranged:

  side_by_side   old | new             mine | merged | other
  stacked        old / new             mine / merged / other
  four_way       (merges)              mine | base | other / merged

`gl` cycles the layouts of the current kind (diff or merge).

STATUS                                                       *diffmerge-status*

The file panel lists what `git status` shows: Conflicts / Staged (`git diff
--staged`) / Unstaged (`git diff`) / Untracked; the log below (`gL`,
|diffmerge-log|) shows commits in the same windows. A changed file opens as

  HEAD | WORKING TREE | INDEX
  what was   what you work on   what will be committed
  read-only  editable           (the index)

with only the columns that differ: nothing staged yet shows HEAD | WORKING
TREE, everything staged shows HEAD | INDEX. The columns follow every (un)stage,
from the diff windows or the file panel alike (a line, a hunk, the file, `S`,
`U`, discarding): the column a change moves into always appears, so a line you
(un)stage stays in view, and a column that became identical to its neighbour
goes away. Only these actions remove a column: saving a file, unsaved edits or changes made
elsewhere (lazygit, a terminal) never close the window you work in. The INDEX
column is read-only here. A file listed under both Staged and Unstaged opens
the same view.

Binary files, symlinks (shown as "Symbolic link → target") and submodules
("Subproject commit …") are staged as a whole from the file panel.

With three columns each change is painted by its state (Vim's own colours
would compare every column with every other):

  U  amber   unstaged: only in the working tree
  S  green   staged: the index has it
  ±  violet  mixed: the index holds another version (e.g. partly staged)

Inside a changed line the changed characters are painted in a stronger tone
(|diffmerge-inline|): an unstaged line against INDEX, a staged one against
HEAD.

Staging:
- `<Space>` toggles the line under the cursor between unstaged and staged, in
  any column, then moves on to the next change of the same state, so pressing
  it again walks through them (lazygit style). A changed line goes together
  with the line shown next to it (the alignment on screen).
- `-` toggles the whole hunk; visual `-` / `<Space>` the selected lines.
- `X` discards the unstaged hunk under the cursor (visual: the selected
  lines): the working tree gets the INDEX version back. The file is saved
  right away without autocommands (no format-on-save); if it had other
  unsaved edits it is left unsaved instead. `u` (and |:w|) brings the change
  back. Staged changes are not discarded: unstage them first; new files have
  no version to go back to (`X` in the file panel deletes them).
- When staging or discarding leaves no visible difference, the final newline
  (which a line diff does not show) moves along, so nothing is left behind
  that could not be pointed at.
- File panel: `-` / `<Space>` stage / unstage the file, directory or section
  (visual: every line). On a conflict it marks the file resolved (`git add`)
  after checking for unresolved conflicts / markers. `S` stages everything,
  `U` unstages everything, `X` discards unstaged changes / deletes untracked
  files (asks first).
- File panel, on a conflict: `<leader>1` / `<leader>3` resolve the whole file
  with LOCAL (ours) / REMOTE (theirs), e.g. for binary files or lockfiles, and
  mark it resolved; if that side deleted the file, it is deleted. `git
  checkout -m <file>` brings the conflict back.

`status.three_way = false` switches back to separate two-way diffs: Staged is
HEAD | INDEX, Unstaged is INDEX | WORKING TREE (the INDEX side is editable
there and |:w| writes it to the index); `-` / `<Space>` then stage in Unstaged
and unstage in Staged.

The view refreshes when files are written, when Neovim gets focus and when the
git directory changes (e.g. lazygit or a terminal).

STASHES                                                     *diffmerge-stash*

`s` in the file panel (or the log panel: no files there) stashes, from a
menu:

  Staged changes          what you staged (lines, hunks, files) goes, the
                          rest stays (`git stash push --staged`)
  This file / These files the files under the cursor or selection
  All changes             `git stash push`
  ... and untracked files `--include-untracked`
  ..., keeping the staged ones in place
                          `--keep-index`: to try out what you are about to
                          commit

It asks for a message; empty, git writes its own ("WIP on <branch>: ...").
Files with unsaved changes have to be saved first. Staged and unstaged
changes on neighbouring lines of a file can be stashed apart (git itself
cannot do that with `--staged`); on the same lines they cannot, and nothing
happens.

Stashes are listed below the changes, one folded section each
(`stash@{0}  On master: message`); `l` / `<CR>` unfold one. A stashed file
opens like a change, read-only: STASH BASE (the commit it was made on) |
STASHED WORKING TREE | STASHED INDEX, only the columns that differ. On a
stash or its files, `s` offers apply (the staged part staged again), pop
(apply and drop) and drop; `X` drops it (asks first). An apply that
conflicts shows the files under Conflicts; git does not apply a stash to
files with changes of their own.

COMMITTING                                                 *diffmerge-commit*

`cc` in the file panel (or the log panel) commits what is staged, `ca` amends
the last commit,
and `c` alone offers both from a menu. `:DiffMerge commit [args]` runs `git
commit` with any arguments, quoted as in a shell (`-m "two words"`). It is
git's own commit: git's message template (your commit.template, the merge
message when a merge is finished, the last message when amending), its hooks,
its cleanup of `#` lines. The message opens in a window below (filetype
gitcommit): `:wq`, `:x`, `ZZ` commit (`:q` too, when you left the message as
git wrote it); `:q!` or `ZQ` aborts, also when git filled the message in. If
you went on working elsewhere meanwhile (a slow pre-commit hook), the window
opens without taking you there. While git runs before the message (hooks),
`cc` again offers to stop it. Until the commit is done, what is staged stays
as it is (git commits the index it started with) and the status view does not
close. What git says (the new commit, or why not, e.g. a failing hook) shows
when it is done; a message rejected after you wrote it (a commit-msg hook) is
offered again by the next commit of the same kind (`cc`, `ca`, continuing),
when git offers the message it was written over again.

                                                        *diffmerge-operation*
While a merge, rebase, cherry-pick, revert or `git am` goes on, the file
panel says which (a rebase with its progress: `REBASING topic (3/7)`, `onto
1a2b3c4`) and what to type, and `cc` continues it (`git merge|rebase|
cherry-pick|revert|am --continue`): the message of its commit opens like a
commit's when git asks for one (a merge, a commit of a rebase whose conflicts
you resolved; a cherry-pick or revert keeps git's message, `ca` amends it);
`:q!` aborts the message, the operation goes on. Not while files are in
conflict or have unsaved edits (what DiffMerge put into a conflicted file to
show it does not count). `c` offers:

  Continue                 as `cc`
  Commit what is staged    a new commit (a rebase stopped to edit a commit, or
                           at a `break` / failing `exec`: splitting a commit)
  Skip                     the commit being applied is left out (a
                           cherry-pick, revert, `git am`, a rebase stopped in
                           conflict; not between two commits of a cherry-pick
                           or revert: "(between two commits)")
  Abort                    everything goes back to before it started

Skipping and aborting ask first, naming the files whose unsaved edits git
writes over. `ca` still amends (a rebase's stops to edit a commit). While the
todo list of a `git rebase -i` is still open in an editor, nothing is offered
and commits wait too.
`:DiffMerge continue|skip|abort` do the same.

                                                          *diffmerge-rewrite*
On a commit of the log, the `c` keys also rewrite your branch up to it:

  cf    fixup: what is staged becomes part of that commit (`git commit
        --fixup`, whose line in the rebase's todo list DiffMerge moves right
        after that commit)
  cs    squash: the commit into its parent, both messages in the message
        window to make one of
  cr    reword: its message in the message window
  cd    drop: the commit left out (asks first)

`c` on a commit offers them too. Each is a `git rebase -i --autostash
--no-autosquash` (your uncommitted changes are put aside and come back;
pending `fixup!` / `squash!` commits stay where they are) whose todo list
DiffMerge writes: you never edit it. Only the history of HEAD is rewritten,
not with a merge commit in it or after it, not while a merge, rebase, ... is
in progress or files are unsaved. A commit already in the upstream branch (for
a squash: its parent) is asked about first: pushing it afterwards needs
--force-with-lease (`P` offers it).

`:q!` in the message window of a squash or reword undoes the whole rewrite. A
conflict on the way stops it like any rebase (|diffmerge-operation|); a reword
a commit-msg hook refuses stops at that commit: `ca` writes the message again,
`cc` goes on. When it is over you are told where the branch was: `git reset
--keep` there brings it back (after a fixup `git reset --soft`: the fix staged
again). A fixup that does not happen (refused by a hook, aborted) takes its
commit back: what was staged is staged again (one skipped in a conflict: you
are told how to get the fix back). If your uncommitted changes do
not apply on the rewritten branch, git keeps them in the stash and they show
under Conflicts.

FETCH / PULL / PUSH                                         *diffmerge-remote*

`F` fetches, `p` pulls, `P` pushes (the file panel and log panel of the
status view; `:DiffMerge fetch|pull|push [args]` with any arguments). They run in the
background, one at a time per repository; what git says shows when it is done,
with how far ahead / behind the upstream branch is (also in the view's title).
While one runs, `F`, `p` or `P` offers to stop it (git and its hooks);
quitting Neovim waits for it a while. Status and diff views follow them; the
log keeps the selected row and what you marked.

  pull    plain `git pull`: your git config decides how (pull.ff, pull.rebase).
          Not during a merge, rebase or commit; files with unsaved changes have
          to be saved first. Conflicts show under Conflicts. Stopping a pull
          can leave files half updated: you are told what it left.
  push    a branch without upstream, when git refuses (push.default simple or
          upstream): offered to push it to its remote (pushRemote,
          remote.pushDefault, origin; several: asked) and track it there.
          Pushed without one (push.default current): offered to track it.
          Rejected because the remote's branch has commits that are not here:
          - not fetched yet: `F` fetches them, `p` pulls them;
          - fetched but not in your branch: `p` pulls them;
          - your branch was rewritten on top of them (an amend, a rebase):
            offered `--force-with-lease --force-if-includes`, which
            overwrites the remote only if it is still what was fetched last;
            never `--force`.

BRANCHES                                                  *diffmerge-branches*

`b` in the file panel (and on the Working tree / Index row of the log)
switches branches (`git switch`), from a picker (|vim.ui.select|): your local
branches, most recent first, with how far ahead / behind their upstream
branches are, the current one marked `*`; the remote branches that have no
local branch yet (picking one makes a local branch tracking it); and a new
branch from here (it asks for the name). `:DiffMerge switch [args]` runs `git
switch` with any arguments; without them it opens the picker.

`b` on a commit in the log panel checks that commit out: the tip of a local
branch switches to that branch (several there: which one; the one you are on:
nothing to do). Otherwise a menu: for a remote branch there without a local
branch of that name, a local branch following it (listed first); the commit
itself, detached (`git switch --detach`; not when HEAD is already detached
there); a new branch there (it asks for the name). A branch checked out in
another worktree cannot be switched to: the menu names it and offers the
others.

It runs like fetch / pull / push (in the background, one at a time; `b`
while another one runs offers to stop it), not during a merge, rebase or
commit; files with unsaved changes have to be saved first. When uncommitted
changes are in the way, it offers to stash them, switch, and bring them back
there (staged changes staged again when they fit the index there, else as
unstaged changes); only that stash is taken back, never another. Changes that
do not apply cleanly there show under Conflicts; the stash ("DiffMerge:
switching to ...") stays until you drop it. Untracked files in the way (the
branch has files of its own there) are named: move them away first.

------------------------------------------------------------------------------
DIFF                                                           *diffmerge-diff*

`:DiffMerge diff` understands the same arguments as `git diff`:

  git diff                    index -> working tree
  git diff --staged [C]       C (HEAD) -> index
  git diff C                  C -> working tree
  git diff A B, git diff A..B A -> B (the same thing: two snapshots)
  git diff A...B              merge-base(A, B) -> B (changes on B since it
                              forked from A, what a pull request shows)
  git diff C^!                C^ -> C

Paths are relative to the current directory, as on the git command line.

Note that `A..B` means something else in `git log` (commits in B that are not
in A); in `git diff` it is just the two snapshots.

LOG / HISTORY                                                   *diffmerge-log*

The status view has the log of the repository at the bottom: `gL` (in any
window of the view) or `:DiffMerge log` shows and hides it; `:DiffMerge log`
from elsewhere opens the status view with it shown. It is `git log --graph`
with git's own colours. The line format is configurable (`log.format`, a git
pretty format); the default mirrors a `--graph --oneline --decorate` "tree
view" with author and date.

The row under the cursor decides what the file panel and diff windows show:

  Working tree              the status (|diffmerge-status|): staging,
                            discarding, stashes, conflicts
  Index                     what a commit takes: Conflicts and Staged
                            (unstaging works there)
  a commit C                git diff C^ C, read-only (`^` cycles the parents
                            of a merge)
  `m` on two rows A, B      git diff A B       older side on the left;
                                               `t` toggles git diff A...B
  visual rows + <CR>        git diff O^ N      combined changes of the
                                               selected commits O..N

Commits and comparisons are read-only: the staging keys say so (the Working
tree row stages). Hiding the log keeps what it selected; `:DiffMerge` goes
back to the working tree and clears the marks. The first time the log is
shown, it starts on the Working tree row, unless the status has nothing to
show (no changes, no stash): then on HEAD.

A visual selection must be one line of history: exactly the commits of
`git rev-list O^..N`. If it is not (e.g. rows of two branches), you are told
what is included / missing and asked whether to show `git diff O^ N` anyway.
Selecting the pseudo rows too compares against the working tree / index.

The log follows the repository: when the branches move (a commit, fetch,
pull, push or switch; one made elsewhere when the view refreshes, see
|diffmerge-status|, or `R`) it reloads. The old log stays on screen until the
new one is complete; the cursor stays on its row, and the marks are found
again by their commits (a marked commit that is gone, e.g. amended, clears the
marks). The Working tree / Index rows count the changes as they change.

`g^` toggles --first-parent, `a` all branches / HEAD only, `f` asks for extra
`git log` arguments (--author=, --grep=, --since=, ...), `K` shows the commit,
`Y` yanks its hash, `b` checks it out (on the Working tree / Index row: the
branch picker; |diffmerge-branches|), `R` reloads. The keys of the whole
repository work there too: `s` stashes, `c` / `cc` / `ca` commit, `F` / `p` /
`P` fetch / pull / push.

`:DiffMerge log <args>` and `:DiffMerge history` open views of their own: the
log of those paths (of lines for `git log -L`, without the Working tree /
Index rows) and the status of those paths only. `S` / `U` stage / unstage
those paths; a stash takes all changes.

MERGE                                                         *diffmerge-merge*

Conflicted files open in a merge layout (default: mine | merged | other).
A file with git's conflict markers keeps git's merge: everything outside the
blocks stays as it is (git's own merge, rerere resolutions, fixes made by
hand), and every block is an unresolved conflict showing its BASE text. The
conflicts are git's blocks, also where git joined nearby conflicts into one
block or split one into two; any marker style (merge, diff3, zdiff3) and size
(gitattributes `conflict-marker-size`). A block changed by hand (inside its
markers or right next to them) stays as it is, markers included, unresolved
until you pick a side or remove the markers. Blocks that LOCAL, BASE or REMOTE
have as text (a file showing conflict markers) are text. Without markers (a
file resolved by hand or by rerere, or saved half-resolved), git's merge of
the three versions (`git merge-file`, in the repository's merge.conflictStyle)
gives the conflicts; changes of one side, or identical changes of both, are
applied as git applied them.

Native diff colours are muted in merge windows (Vim compares every window
with every other), and 'diffopt' "linematch" is suspended while a merge is on
screen so that all versions of a chunk line up. Each chunk is painted by what
it is:

  sign  L / R / =   auto-merged from LOCAL / REMOTE / both
  sign  !           unresolved conflict (red)
  sign  1 3 13 ∅    resolved with LOCAL / REMOTE / both / nothing
  sign  ✎           edited by hand (counts as resolved)
  sign  ✓           (side windows) this side is part of the resolution

Inside changed lines the changed characters are painted in a stronger tone
(|diffmerge-inline|): in a conflict LOCAL and REMOTE against each other (what
the choice is about), a one-sided change against BASE, MERGED against BASE.

Resolving, in any window of the merge layout, for the chunk under the cursor:

  <leader>1   toggle LOCAL (mine)      toggling appends / removes, so
  <leader>2   toggle BASE              <leader>1 then <leader>3 gives
  <leader>3   toggle REMOTE (theirs)   "mine, then theirs"
  <leader>0   resolve with nothing
  ]x / [x     next / previous conflict
  ]c / [c     next / previous change

The state of a chunk is derived from its content, so undo and manual edits
just work. Undo stops where the merge started: git's markers do not come back
(redo still works). Lines typed at the very edge of a chunk (e.g. `o` on the
line above it) stay outside of it, so an unresolved conflict never becomes
"resolved" by accident. Modify/delete conflicts stay unresolved until you pick
a side; an emptied file is offered for deletion (`git rm`) when you mark it
resolved. Saving writes what you see. Re-opening a file that was saved
half-resolved finds the unresolved conflicts again (they still show their BASE
text); in a new Neovim session they are found in git's merge in the
repository's merge.conflictStyle, so a file whose markers came in another
style (`git checkout --conflict=diff3`) may then show its conflicts joined
differently.

During a rebase "ours" is the branch being rebased onto and "theirs" is your
commit; the window bars say so.

                                                             *diffmerge-inline*
Vim's own inline highlighting is muted in merge windows and in the three
column status view; DiffMerge paints the changed characters itself, following
'diffopt': "inline:char" (default), "inline:word", "inline:simple" (first to
last changed character) or "inline:none", and "iwhite", "iwhiteall",
"iwhiteeol", "icase". Changes to 'diffopt' apply at once. The lines of a
changed block are compared row by row, the way these views show them; lines
longer than 1000 bytes are not refined. 'cursorline' would cover these
colours on the cursor's line, so these windows set 'cursorlineopt' to
"number": the cursor line shows in its line number only.

5. GIT DIFFTOOL / MERGETOOL                                     *diffmerge-git*

In `~/.gitconfig`: >gitconfig
    [diff]
      tool = diffmerge
    [difftool]
      prompt = false
    [difftool "diffmerge"]
      cmd = nvim -c \"DiffMerge difftool\" -- \"$LOCAL\" \"$REMOTE\" \"$MERGED\"
    [merge]
      tool = diffmerge
    [mergetool "diffmerge"]
      cmd = nvim -c \"DiffMerge mergetool\" -- \"$LOCAL\" \"$BASE\" \"$REMOTE\" \"$MERGED\"
      trustExitCode = true
    [alias]
      mt = !nvim -c \"DiffMerge conflicts\"
<
`git difftool -d` passes two temporary directories; they are compared with a
file panel. When the right side is the working tree (not with `--staged`),
its files are edited: by default git links them into the temporary
directory, so saving writes the working tree file at once; with
`--no-symlinks` git copies the edits back when Neovim exits.

`git mergetool` runs the tool once per file. Neovim exits with code 1 (git
restores the file and reports the merge as failed) while conflicts are
unresolved or the merged file is unsaved; `:DiffMerge abort` quits with 1
explicitly. To go through all conflicts in one Neovim, use
`:DiffMerge conflicts` (the `git mt` alias above).

6. KEYMAPS / ACTIONS                                        *diffmerge-keymaps*
                                                            *diffmerge-actions*

All mappings are buffer-local and only exist while a view shows the buffer;
mappings they shadow are restored afterwards. `g?` lists the keys of the
window it is pressed in, by function (that window's own first). Change them
with `keymaps.<group>[lhs] = action | function | false`. A panel's own group
(`file_panel`, `log_panel`) wins over `view` and `repo` in that panel; `false`
there turns a key of them off in that panel only.

The scheme: `g` and a letter for a part of the view, in every window; the
keys of the whole repository the same in both panels (group `repo`); staging
the same in the file panel and the diff windows (`-`, `<Space>`, `X`); `]` /
`[` to move on.

view (every window)
  ]f / [f    next_file / prev_file
  gF  gL     toggle_files / toggle_log      the file panel / the log panel
  gl         cycle_layout
  gW         toggle_whitespace
  g?         help

repo (file panel and log panel of status views)
  c  cc  ca  commit_menu / commit / commit_amend
  s          stash
  F  p  P    fetch / pull / push

file_panel                           log_panel
  <CR> o    select                     <CR>  select (visual: combined)

7. CONFIGURATION                                             *diffmerge-config*

Defaults: >lua
    require("diffmerge").setup({
      layout = {
        diff = "side_by_side",   -- "side_by_side" | "stacked"
        merge = "side_by_side",  -- "side_by_side" | "stacked" | "four_way"
      },
      file_panel = { width = 30, tree = true, show_stats = true },
      log_panel = { height = 15 },
      log = {
        format = "%<|(15)%C(yellow)%h%C(reset) %C(auto)%d%C(reset) %s "
          .. "%C(240)by %an%C(reset) %C(244)%ad(%ar)%C(reset)",
        date = "format:%Y-%m-%d %H:%M:%S",
        all_branches = true,           -- :DiffMerge log
        history_all_branches = false,  -- :DiffMerge history
        first_parent = false,
        follow_renames = true,
        max_count = nil,
      },
      status = { three_way = true },     -- HEAD | WORKING TREE | INDEX
      diff = { algorithm = "histogram" },  -- merge chunks
      merge = { virtual_text = true },
      auto_preview = true,     -- moving in a panel shows the entry
      preview_debounce = 80,
      watch = true,            -- watch the git dir in status views
      icons = {
        folder_closed = "▸", folder_open = "▾",      -- folders (file panel)
        expander_closed = "▸", expander_open = "▾",  -- sections
        mark_from = "A", mark_to = "B",              -- log marks
      },
      keymaps = { ... },       -- see |diffmerge-keymaps|
    })
<
The native diff windows use 'diffopt' (Neovim 0.12 defaults to

9. LUA API                                                      *diffmerge-api*

    local dm = require("diffmerge")
    dm.status({ conflicts = false })
    dm.diff({ "main...HEAD", "--", "lua/" })
    dm.log({ args = { "--author=me" } })
    dm.history(path, { range = { first, last } })
    dm.difftool(left, right, name)
    dm.compare(left, right)
    dm.commit({ "--amend" })
    dm.remote("push", { "--tags" })   -- "fetch" | "pull" | "push"
    dm.switch({ "topic" })            -- no args: the picker
    dm.mergetool(local_, base, remote, merged)
    dm.current()   -- view of the current tab
    dm.close()
